# CourseApe v1.0.2 Update Check Design

Status: Approved for implementation

## Goal

Publish all changes since v1.0.1 as v1.0.2 and add a non-blocking update notification that checks npm's `latest` dist-tag at most once every four hours.

## Architecture

The Rust binary owns update checking so npm installations and directly downloaded GitHub binaries behave consistently. A focused update module runs before normal command dispatch and never writes to stdout.

The module queries:

`https://registry.npmjs.org/@dyliu0306%2Fcourseape/latest`

It reads the response's `version` field, compares it with `env!("CARGO_PKG_VERSION")`, and writes an update notice to stderr only when the remote semantic version is newer.

## Cache

The cache uses a fixed file in the CourseApe application data directory:

`update-check.json`

It stores:

- `checked_at`: UTC RFC 3339 timestamp
- `latest_version`: last successfully returned npm version

For four hours after a successful check, commands use the cached latest version and do not make a network request. A stale, malformed, missing, or unreadable cache triggers a network attempt. Cache failures do not fail the command.

## User Experience

When the installed version is old, stderr displays:

```text
CourseApe 有新版本：目前 1.0.1，最新 1.0.2。
更新：npm install -g @dyliu0306/courseape@latest
```

The notice does not use stdout, ensuring Agent JSON output remains valid. No notice is displayed when the installed version is current.

The check applies to normal commands and `--version`. It has a short HTTP timeout so it does not materially delay command execution.

## Failure Handling

Network timeout, offline operation, npm errors, malformed responses, invalid versions, or filesystem errors are ignored. CourseApe continues executing the requested command normally. A failed network check is not cached as successful, allowing a later invocation to retry.

## Version Comparison

Use semantic version comparison rather than string ordering. Stable versions are the required release path. Pre-release metadata is parsed correctly if encountered, but only a strictly newer remote version triggers the notice.

## Testing

Unit tests cover:

- semantic version ordering, including `1.0.10 > 1.0.2`
- current and older remote versions do not produce a notice
- four-hour cache freshness boundary
- malformed cache and malformed npm response fail open
- notification text contains current version, latest version, and update command

Release verification remains:

- `cargo test --locked`
- `cargo clippy --locked -- -D warnings`
- npm wrapper build and packed smoke test
- release version invariant for v1.0.2
- native binary `--version` smoke tests

## Release Scope

v1.0.2 includes all commits after v1.0.1, including Agent installation guidance, complete Skill command documentation, HTML grade parsing, retake handling, department-priority course matching, deterministic requirement storage, automatic PDF text extraction, university-wide graduation rules, language-center selection rules, syllabus-first course-content guidance, and this update check.
